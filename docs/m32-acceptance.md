# M32 acceptance and evidence classes

This document defines required evidence; it does not mark pending checks passed. Exact results and source SHAs are maintained in [the M32 report](reports/milestone-32.md).

| Surface | Required evidence | Scope/limit |
| --- | --- | --- |
| Linux source onboarding | Production setup/start on Ubuntu22.04 and24.04; exact tracked snapshot; container-built private runtime; complete exported inventory; rerun preservation; native Electron | Actual disposable engine/OS, not a customer installer or live provider |
| Windows source payload | Linux cross-staging, complete Windows inventory, actual private Python imports and Electron launch after relocation without source-tree dependency links | Native Windows payload evidence; does not prove Docker Desktop or managed NTFS binds |
| Bootstrap faults | Private root/native parent pins, canonical aliases/ADS/hardlinks/reparse refusal, bounded streams/deadlines, source archive preflight, missing/changed selection, no automatic replay | Synthetic engine tests are labelled separately from native path tests |
| Integrated runtime | Existing actual container foundation, worker/PTY/install, Runtime disk-SQLite, M30 transfer and M31 lifecycle matrices; full native-tool/goal/guidance/skill/plan/editor/approval suites | Preserves accepted implementation boundaries; fixture provider is not STARK acceptance |
| Windows Docker device | Exact local D storage/native DACL and Linux bind identity; native and Linux SQLite probes; route/transport; dependency link tags/targets; crash/recreate | Open unless an authorized disposable Windows Docker environment actually exercises it |
| Human/device lifecycle | Native picker/cancel, dirty close, whole host job survival, actual close during privileged container install, independent install decision | Open; synthetic dialog returns and mocked engine replies do not satisfy it |
| Live provider | Work-only STARK native tools/streaming/correlation and sustained role workflow | Explicitly deferred; no credential polling or private document publication |
| Customer distribution | Signed/unsigned status, complete manifest, images/runtime provenance, notices/source, clean machine upgrade/uninstall/data preservation | M21 paused; no release acceptance from source CI |

Windows worker topology continues to refuse every reparse point. Ordinary dependency links created by a Linux package manager may therefore prevent subsequent Windows-backed worker dispatch. No symlink tag, junction or Linux interpretation is guessed or relabelled. Enabling a measured worker-only representation requires native no-follow tag/payload/identity, exact fixed-image same-project contained link/target proof, mapping/session freshness and final dispatch binding, with coordinator review. Source/import/export/private-root/ancestor refusal remains unchanged.

Known failed receipts remain part of the report. Subsequent passing runs do not establish an unmeasured cause for earlier M30/31 preservation or PTY failures. Accepted reply loss remains uncertain; recovery is cleanup-only with exact ownership and never arbitrary adoption, install replay or unrelated stops.

Source staging uses an Ubuntu22.04 private Python ABI baseline and records the actual build package inventory. A package compiled on24.04 alone cannot establish22.04 support. Native modules optional to the host backend are excluded from the desktop closure; project tools remain inside Linux workers. Target execution and actual extension imports are required after relocation.
