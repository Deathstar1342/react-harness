## Proposed bounded interface (coordinator review requested)

1. Host source supervision runs a Python 3 standard-library broker, launched by the existing explicit Linux container source script. No host Node/npm/Bubblewrap/helper is required. The later Electron supervisor can launch this same narrowly configured broker; M31 owns bundled-runtime and desktop lifecycle integration. Only the host broker invokes fixed Docker argv. Session initialization is host-only, from the verified storage selection and locally built/pinned worker image ID. No model/API supplies images, mounts, executables or daemon options.
2. Controller transport uses a private Unix socket directory mounted only into the controller. A fresh random session key authenticates bounded, canonical JSON requests/responses with HMAC, nonce, expiry and durable replay rejection. Workers never mount this directory or controller state/config. The broker journal is host-only under runtime. Restart rotates the session; old prepared claims are invalid, accepted/running claims remain uncertain and never replay. Existing containers are not adopted from names or supplied IDs.
3. The controller resolves its registered project into a managed relative identity beneath /workspace; the broker independently resolves exactly one canonical host directory beneath the selected workspace, rejecting links, nested mounts and unsafe metadata. The immutable project identity includes storage ID and directory identity. Worker mounts contain only this project and its dedicated dependency/cache paths. Protected files retain masking/refusal rules. Each owned shell context has its own container/process identity; only broker-generated opaque handles cross the boundary.
4. `prepare` binds a UUID claim, managed project, shell-context identity, exact bounded command/operation digest, timeout <=600000, output <=1000000, fixed runtime class, and one-use expiry. It may prepare infrastructure but cannot run the project command. After preparation, the controller reruns async freshness checks, then synchronously commits the existing final runtime claim and immediately submits `activate` with the exact prepared token/digest. The broker durably consumes it before execution. This is a durable authorization/activation boundary, NOT a synchronous cross-process freshness guarantee. Steering after authorization requests cancellation; effects after acceptance remain possible. Lost activation replies are uncertain, never not_started or retried.
5. Only trusted callback veto before activation plus confirmed preparation cleanup yields not_started. Prepare/activate/observe/cancel/close are strict schemas; unknown fields reject. Observation uses exact session/project/claim/job ownership and monotonic output offsets. PTY state/cwd persists per owned chat/agent context. Python, tests and background jobs retain existing runtime callbacks, mutation reservations, file/version/lease checks, native correlation and process evidence. Fixed Git runs only through a fixed-argv worker operation with existing filter/hook suppression. Cleanup failure quarantines the scope and preserves uncertainty/ownership. No arbitrary PID adoption or restart execution.
6. Worker networking must not expose host/controller/broker/private services. Proposed public HTTP(S) egress uses an isolated worker network and a dedicated credential-free proxy with public-address resolution checks; it replaces the registry-only allowlist while denying private/loopback/link-local targets. The proxy receives no provider or broker secret. Unsupported outbound protocols fail explicitly. No host networking, privileged containers, shared PID namespaces or Docker socket mounts.
7. Installs retain independent Ask/Auto/AI policy, reviewer revision, bounded preview, fallback, exact decision/target binding, auditing and trusted reconciliation. The target is an immutable per-project worker image generation. Root apt executes ONLY in a disposable maintenance container with no project/cache/controller/control bind mounts. It cannot change host/project storage permissions. The broker pins resulting image identity and switches workers only after confirmed completion and idle cleanup; uncertain transactions are never replayed. Packages in that image are separate from project dependencies/cache, which persist under dedicated storage. Completed reviewed recipes and exact versions are recorded; rebuild is an explicit new preview/approval, never startup restoration. Existing pending/uncertain install identities remain tied to their original target. Minimal UI labels identify execution-container scope.

## Coordinator review — refinements accepted

The coordinator approved the proposed contract with explicit Python 3 prerequisite detection (no provisioning), transport/runtime separation for M31, and no assumption that Windows Docker Desktop can mount a host Unix socket. Linux source support is the first transport; a future host-initiated authenticated channel is a separate adapter.

Canonical wire v1 uses sorted ASCII-escaped JSON, Unicode scalar strings, safe integers only, strict op schemas, duplicate-key/nonfinite rejection, bounded messages and deadlines, session/nonce-bound HMAC replies, and an fsync-backed bounded replay/claim journal. Broker subprocess environments are allowlisted and independent of provider/DOCKER/Python/Node injection environment. Worker image IDs and local engine identity are host-resolved. Authenticated live broker capability determines execution availability.

Networking uses network-none workers with their own loopback and a dedicated read-only public egress Unix-socket bridge. This supersedes the isolated-bridge suggestion above. Public HTTP(S) connections pin vetted public DNS addresses; private, mapped, alternate, metadata and IPv6/private bypasses require actual negative tests. TLS remains end-to-end for CONNECT. Maintenance has no mounts; its network mechanism must likewise be bounded without host apt or privileged Docker.

Install bindings include storage, project and immutable base image generation. Publication requires a completed transaction plus successful image commit and old-context drain; switch/cleanup failures remain uncertain. Prepared claims and evidence are invalidated by generation changes, and shell state loss is explicit. Root maintenance transactions never replay. Protocol observation is not a general uncertainty waiver. Raw worker stdout is untrusted output; authoritative exit/cleanup evidence must be owned and protected from the project process.

## Protected runner and install-target decisions

Coordinator approved per-command real PTYs with protected OS wait status, persistent bounded cwd/exported environment, and explicit loss of shell-local functions/aliases/options between commands. Related shell-local workflows belong in one command. Captured state is untrusted, cannot affect root/host configuration, and applies only after full non-root child privilege drop. Missing capture reports state loss. Root-runner CAP_KILL is proposed solely for exact private-namespace child-group termination after UID drop; daemon-owned container cleanup remains mandatory for cancellation/timeouts. No host PID namespace or privileged mode.

Profile-wide install policy/reviewer revision is separate from per-project immutable typed container targets. Discovery for A must not reset global policy or stale B. Original target/preview lineage is retained for recovery after later generation changes. The existing deterministic apt resolver/trust/closure/size rules will be reused inside the maintenance image with a typed container adapter, never fabricated host machine IDs. A transaction-specific network-none companion mounts only the public egress socket; mount-free maintenance joins that exact companion network namespace. Both identities/cleanup are broker-owned, never adopted after restart.
