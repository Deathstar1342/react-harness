## Concrete identity and lifecycle contract

- Inspector observation is separate from execution/acceptance. New request accounting begins before invoking a provider or scheduler. A generated local request UUID identifies that invocation; upstream request IDs are optional sanitized correlation, never a deduplication key or authority. Existing original project/chat IDs, root architect frame ID (run), active frame ID (task), role, generation, request ordinal, original human message IDs and optional exact PlanStepRef are captured from Runtime, not model text. Steering retains the run/frame identity and captures current generation/human provenance for each request; a new architect root is a new run. No old RunState rewrite or invented historical run identity.
- Capture the exact selected model string at invocation (bounded), role and purpose (`conversation` or `compaction`), requested output bound and original event IDs. Retain original returned native call IDs only after normal native validation; bind each to its request/frame without parsing/re-executing tool arguments. Atomic native call/result sequencing and global call-ID checks remain authoritative. Inspector rows cannot make an invalid batch executable.
- Persist bounded scalar identity columns plus a small schema-validated request envelope in a dedicated SQL table. Embedded identities must exactly match original SQL keys/chat/project/run/request references. Parse original bytes with duplicate-key rejecting native JSON; reject inconsistent roots, references, repeated/conflicting IDs or malformed records rather than repairing them. New tables participate in existing native write/final-COMMIT gates. Reads use native operation/observer health and shared poison gates; no private-state cache, absence waiver or second database connection bypass.
- Record start before dispatch and terminal observation after completion or failure. Start-only after crash/reply loss remains `outcome unknown / no terminal observation`; GET does not mark it failed or repair it. Refusal, truncation, timeout, abort, HTTP/transport/malformed errors have allowlisted outcome codes, without raw error/provider payloads. No automatic provider retry is added. Production managed hooks already require provider internal retries disabled; explicitly snapshot that accounting scope. If adapter retries are enabled outside that path, expose bounded attempt observations (maximum existing 3), each separately identified; never silently represent multiple attempts as one known-cost request.
- Provider adapter exposes a backend-only bounded observation callback for validated provider-reported usage and safe attempt metadata. One usage observation is a cumulative request snapshot, not an additive delta. Repeated identical fragments do not add tokens; differing valid cumulative reports use the latest original validated fragment and retain a visible replacement/conflict indicator. Callback/result disagreement is flagged, not summed. No usage is derived from streamed text, scheduler estimates, UI event replay or model prose.
- Prefer the adapter's last validated original usage snapshot; successful CompletionResult usage is a fallback for providers/hooks without callbacks, with source labelled. Capture parsed usage before refusal/truncation/cancellation when available. An unsuccessful request may have reported usage; that does not make it successful or establish the provider's final billed total. Absence, malformed reports, reply loss and incomplete streams remain explicitly unknown/incomplete. Provider-reported input=0/output=0 is known zero, never confused with missing counts. Aggregate totals are sums of reported snapshots only and state the number of requests with unknown/incomplete usage. Overflow is unavailable, never rounded or silently saturated.
- Auxiliary compaction requests use the same original chat/run/frame binding and observation wrapper; source purpose is explicit, with a finite per-request observation count. Diagnostics/settings probes are not task requests and are excluded with a coverage statement. No raw compaction archives, hidden prompts or verification ledgers are read for inspector display.
