## Delivered behavior

- Mandatory non-root Bubblewrap namespaces around PTY, Python, tests and fixed Git. Missing prerequisites, unsupported namespaces and unsafe roots fail closed. No Windows or host-shell fallback. Existing persistent cwd/variables, separate agent sessions, bounded output, command queues, cancellation and JUnit reporting remain.
- Direct writable project mount; private per-project home/cache/temp beneath M16's `cache/sandboxes/<root hash>`. Read-only distro tools, exact Node binary/adjacent npm distribution and public CA trust store. App/config/state/descriptor/provider locations, personal home, other projects, host processes/sockets, Windows mounts and WSL interop endpoints are excluded. Proposed toolchain mounts are also checked against effective sensitive paths so unusual M16 overrides cannot leak through a read-only system mount.
- Unsafe roots, nested registered projects/mounts, hardlinks, sockets/special files and external symlinks are rejected. Internal dependency links and exposed distro-interpreter links work. Existing protected files/directories are covered by immutable empty mounts. Protected symlinks are rejected. Root/protected inode identity changes discard idle sessions before the next command; no automatic retry/replay.
- Per-session registry-only CONNECT broker on a private Unix socket, reached by fixed socat inside an isolated network namespace. Exact npm/PyPI authorities only, strict framing, conservative global-address validation of every DNS answer, pinned literal connect address, no host DNS/raw routes, bounded connections/headers/bytes/time. TLS stays end-to-end. Direct localhost/LAN/metadata/Internet access and proxied non-registry destinations fail. Install hooks remain confined.
- Cancellation/disposal awaits namespace/PTY exit and broker/tunnel cleanup. Every disposal failure becomes `SANDBOX_CLEANUP_FAILED`; failed/in-flight sessions stay tracked and the scope is quarantined. Queued and other-agent work are denied; backend shutdown rejects rather than releasing M16 ownership after uncertain cleanup.
- Explicit POST `/api/projects/:id/sandbox/reset` with strict `{}`. Registered project only; same-origin/JSON/runtime/request/dirty/pending/background/removal-recovery guards. Awaited reset deletes only private sandbox storage, preserving source, `.venv`, `node_modules`, app configuration/state. Existing and new requests are gated across the drain.
- Fixed empty-repository initialization replaces ambient host `git init`. Linux tests verify that resulting repositories work through sandboxed Git. Fixed Git status/diff preserve literal-pathspec, filter/fsmonitor/hooks and credential-output safeguards.

## Interface changes and compatibility

`ToolService.configureSandbox` and `resetSandbox` are optional trusted lifecycle methods, never model/browser-controlled policy. `removeScope<T>` now returns `T | Promise<T>`: synchronous preflight, scope gate, awaited resource drain, final lease check, synchronous mutation. Disk removal repeats token expiry/currentness and canonical identity checks after draining, before token consumption, `removalError` or filesystem mutation. Deferred-drain regressions cover expiry/path swap; initial invalid requests still cannot destroy shell state.

**Intentional restriction:** arbitrary shells see empty `.git`; shell commit/branch operations against imported metadata are unavailable. Fixed `git_status`/`git_diff` remain functional. External Git worktree metadata is unsupported. Native Windows Git success tests now run on Linux only; a Windows regression explicitly asserts `SANDBOX_UNAVAILABLE`. No test-only production bypass was added.

Advisor prompts, `planStep`, ordinary Chat Completions, approval modes, file versions/editor leases, request idempotency and uncertain-action behavior are preserved. Shared contracts and API/setup/architecture docs describe the new boundary.

## Limits and remaining acceptance

- **Concurrent trusted host mutation is not confined.** Pause before introducing secrets/links/mounts or changing protected topology. Existing in-place masked-file edits stay hidden; idle atomic replacement is detected. New unmasked secrets or replacement during an executing command are outside this guarantee. Direct imports are not copied. Arbitrary secrets inside ordinary source cannot be recognized by a filename policy.
- The project/private caches are writable. Malicious packages can corrupt those contents and use the registry capability for exfiltration. The proxy controls destinations, not artifact content, request paths, TLS SNI or package safety. Registry IPs can host shared infrastructure; this is not application-content filtering. Redirects confer no additional CONNECT destination authority.
- Shared-kernel exploitation, CPU/memory/disk exhaustion and same-user external host attacks are residual risks. No VM/cgroup/disk-quota guarantee. Output, proxy and scan bounds are not comprehensive resource isolation.
- Linux requires Bubblewrap/user namespaces, socat, bash, Python venv and Node/node-pty. No tools, helper, kernel policy or distribution were installed/reconfigured on the developer workstation; the Podman WSL distro was untouched. Linux CI is not local WSL, desktop/device/browser or work-network STARK acceptance.
- Public npm/PyPI only; alternate/private registries, Git dependencies, arbitrary URLs and general networking are unavailable. Large transfers are bounded (128 MiB per tunnel, five-minute lifetime). Public certificates in project dependency paths matching credential patterns are masked; applications needing a CA file can use the exposed system trust bundle.
- `npm ci` reported the existing lockfile audit total of five vulnerabilities (two low, one high, two critical). No dependency version/lockfile change or unrelated upgrade was made in M17. Production Vite build retains its existing large-chunk warning.
- Coordinator owns independent final review, main integration/publication and subsequent milestones. Child remains idle after delivery; no user-assistance blocker.
