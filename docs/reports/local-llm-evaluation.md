## Existing behavior and interface assumptions

- The existing configurable OpenAI-compatible adapter uses `/models` and `/chat/completions`. It carries native tool definitions, call arguments and correlated results, assembles bounded SSE fragments, and validates normal finish, refusal and truncation. `POST /api/connection-check` already performs an in-memory echo through a native call and a matching tool-result turn, in both JSON and SSE, with no project tools. Catalog membership and each probe outcome have separate meanings. Reuse this diagnostic and managed provider path where they fit. [Provider contract](../architecture.md#provider-contract)
- Set the same exact catalog ID for Architect, Coder and Critic in a fresh isolated profile before creating chats so their model snapshots match. Configure the backend URL, per-role context limits, output limit and streaming through current settings. The adapter currently requires a nonblank backend key and sends a bearer header. The request supports `max_tokens` but has no general sampling-settings pass-through and does not request `stream_options.include_usage`. Keep endpoint-supported generation settings fixed at the server where possible and record defaults or unknowns. Treat absent usage as unknown. Qualify the agreed route before proposing any change to auth, options or usage handling. A catalog entry alone leaves native capability unknown. [Provider and model configuration](../architecture.md#provider-contract)
- A Runtime run awaits one active role's completion and processes its native calls serially before moving to the next role. The production managed scheduler applies existing account and context limits, and its account concurrency is shared across runs. Live trials admit one run at a time and measure overlap at the request boundary, including compaction. Repeat diagnostics and benchmark trials sequentially. Leave unrelated scheduler and nonlocal behavior intact. [Agent coordination](../architecture.md#agent-coordination)
- Runtime validates the full native batch before effects using the role/mode registry and strict JSON, including required/unknown keys, duplicate keys, exact IDs and terminal-call placement. Transport and handler failures have different evidence. Production bootstrap disables internal HTTP retries, while the adapter alone supports at most two retries on selected transient HTTP statuses. Runtime's bounded follow-up for missing native controls, failed tools and local repair is separate. Verify each bound at its owning layer, including which failures stop instead of generating another request. [Native-tool redesign](../native-tool-redesign.md)
- Retain the structured Plan and the current reconnaissance, task context, Critic evidence, repair/replan and checked continuation paths. Existing validation receipts, Plan progress, goal and queue events, filesystem state and durable Inspector correlations determine outcomes. A returned provider request or model PASS is insufficient for accepted completion. Use test-side capture for any dispatch estimates and exploration counts unavailable from durable evidence. Any product fix must reproduce a concrete failure and use the existing interface or receive separate coordinator review.
