### Explicit authorization and durable claim

It authorizes this fixed snapshot only, with existing approval/mode/goal/plan policies; it does not approve tools, installs, criteria changes, uncertain effects or wider scope. Admission uses one synchronous Store transaction: re-read queue/root/human text bindings and session authorization, check project serialization and fresh guidance/skills/mode/approval/plan/evidence, insert a unique single-use durable task claim, create its new chat and original user message and (only when original human input requests it) goal, prepare native root run, and persist all linked identities atomically.
