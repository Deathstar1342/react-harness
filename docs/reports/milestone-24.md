## Delivered contracts

- Explicit `/goal` and strict create/revise HTTP contracts preserve objective, human criteria/kinds/provenance, stable unchanged criterion IDs and visible superseded revisions. Model plan additions become protected scope; removing/renaming/reusing IDs cannot erase original requirements. Human revisions require exact revision and a reason.
- The existing single serialized native runtime continues authorized unfinished work after architect prose/native frame completion. It pauses or blocks with a reason at bounded quotas, missing input, approval, uncertainty or failure. Ordinary chats remain conversational, and planning still requires explicit Start building.
- The separate final native request binds goal/plan/mode revisions and exact runtime review IDs. Every current/protected step and human criterion needs accepted assignment evidence; checks repeat across freshness awaits and inside cloned COMMIT publication. Coder/critic claims cannot supply completion authority.
- Private original assignment/scope bindings and bounded goal-level failed-check obligations survive popped frames. Unrelated work, criterion remapping and retained-criterion human revisions cannot erase failed checks. Actual helper uncertainty and interrupted effects remain durable; no verdict, restart or goal revision replays/reconciles them. Evidence overflow is explicitly unverified/blocked. No full native Frame/history is duplicated into accepted-goal records, and superseded history/testcase hashes stay out of model context.
- Human-only observational criteria support historical confined reads without fabricated source snapshots. Model-selected observation mode cannot downgrade workspace criteria or excuse any attempted mutation/test/install or failed read. Mixed assignments use workspace verification.
- Narrow approved `server/installs.ts` integration records the existing explicit authenticated recovery result atomically with a private exact request/target/preview receipt. Only succeeded/healthy/matching/no-recovery-required receipts can resolve exact install-associated goal references, at goal creation or explicit Resume. Generic effects and missing/stale/mismatched receipts remain blocked. Original uncertainty remains archived; no execution or helper call is initiated by goal resolution.
- Quiet Goal/status/phase control opens the existing collapsible panel for criteria, blockers, evidence limits, budgets, history and explicit scope edits. Pause/resume, `/btw`, file versions/editor leases, guidance freshness, independent install/workspace policies, backend-only secrets and correlated native groups remain in force.

Exact schemas, bounds, transitions and evidence limits are documented in [API contract](../api-contract.md#m24-durable-goals), [architecture](../architecture.md#m24-durable-goals-and-completion-authority) and [setup](../setup.md#durable-goals).

## Acceptance limits

Synthetic native model replies demonstrate deterministic runtime and prompt construction, not STARK behavior or model judgment quality. Criterion-to-assignment semantic mapping and critic sufficiency remain model judgments; runtime enforces recorded scope, provenance, checks and uncertainty rather than proving arbitrary natural-language goals.

Workspace freshness observes bounded visible regular text under explicit paths. It does not prove outside-scope dependencies, filtered entries, persistent shell cwd/environment, report authenticity or absence of external races. The final aggregate snapshot budget is five seconds; oversized/unknown scope rejects completion. Observation-only evidence is explicitly historical and requires human opt-in.

The no-progress bound counts newly accepted required steps, so a useful long coder task can pause after 16 model turns. Explicit Resume renews quotas; automatic continuation and approval do not. Uncertainty/evidence overflow cannot be cleared with Resume. Relevant failed-check obligations can conservatively require the original binding after a plan remap; human revision must genuinely supersede affected criteria to remove them, with history retained. Backend close/restart never silently starts goal work. There is no app-closed service.

Portable Windows checks, actual headless Chromium/Electron, disposable Linux/PTY/helper CI and installed-device/native-human/live-provider acceptance remain distinct. Work-only live STARK, installed-device/native dialogs, clean-machine and release gates remain deferred. M21 worktree `6fd9` and its uncommitted packaging correction remain untouched.
