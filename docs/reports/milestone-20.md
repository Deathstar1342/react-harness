Electron **42.11.13** runs the existing React UI under an isolated in-memory `abyssus://app` session. Renderer sandbox, context isolation, no Node/webviews, restrictive CSP, denied permissions/downloads/windows/navigation, trusted main-frame IPC validation and Electron webRequest frame/contents validation are explicit. Main owns the bounded fixed-target HTTP proxy and streams SSE; it strips caller credentials/headers, refuses redirects/lifecycle/auth routes and confines canonical packaged assets. The only native operations are status, explicit profile startup, native directory selection, dirty notification and native-confirmed fixed helper maintenance. No shell/executable/URL interface exists.

Production `startBackend` always installs instance transport authentication on API and SSE. Desktop main holds a per-launch capability and verifies M16 signed readiness before attaching. Private bounded stdio carries launch material; no capability enters URLs, renderer storage, project environment or ordinary logs. Browser mode uses one single-use 5-minute terminal-displayed pairing code (10 attempts), then a per-instance HttpOnly SameSite cookie, retaining loopback Host/Origin/JSON checks. Trusted in-process `createApp` fixtures can omit transport auth; no production environment bypass is provided. Local cookie and private-file protection do not defend against arbitrary unsandboxed processes running as the same user.

Separate Linux x64 Node **24.16.0** is downloaded from the official distribution, checked against pinned SHA256 `d804845d34eddc21dc1092b519d643ef40b1f58ec5dec5c22b1f4bd8fabde6c9`, staged with npm and locked production dependencies, and checked for version/native-module ABI/SQLite/node-pty operation. Native code is not rebuilt for Electron. Installation assets resolve independently of cwd; native staging is `build/app` plus `build/runtime`, production Linux/WSL uses `/opt/abyssus/app` and `/opt/abyssus/runtime`. These generated files are ignored, never committed.

Setup explicitly selects native Ubuntu/Debian x64 or an enumerated supported WSL2 distribution. Inventory does not start a distro; Podman/service distros are excluded. Profile home and existing/new/legacy action are explicit and native-confirmed. M16 owns actual migration, original data/receipts and profile/resource locks. Windows native picker accepts only the selected distro's UNC namespace; Windows drive mounts and mismatched distro/traversal fail. Backend project guards remain authoritative. Cancellation does not change editor/project selection.

Readiness is authenticated, startup failures remain visible and owned processes remain tracked. Second app instances focus the current window. Window reload retains backend ownership; backend crash requires explicit reopening of the same profile with existing uncertainty recovery. Deliberate shutdown waits actual local cleanup/process exit, never kills unrelated PIDs/ports, replays an action or promises rollback. Helper maintenance drains the backend before changing authority.

Verified backend identity creates a `profileId/instanceId` session. Main binds the document's proxy to that session and replaces the entire BrowserWindow when it changes, after the dirty-editor guard. React is also keyed by session. Old document callbacks cannot write to a replacement profile. Backend failure preserves existing editor buffers; setup offers a return to the offline editor before deliberate recovery.

Provider settings add an optional public `baseUrl` and bounded HTTP(S) patch field. Userinfo, query, fragment, whitespace/control characters and overlong endpoints are refused. Custom ports/paths remain valid. Effective endpoint changes with an existing key require an explicit replacement/clear in the same atomic save; equivalent URLs preserve credentials. Process environment locks remain authoritative. Subsequent calls snapshot the new endpoint/key together; an in-flight retry retains its original pair. Keys never enter DTOs. New-chat-only model snapshots and advisor prompts remain unchanged.

Helper first-time staging uses an administrator-installed **data-only .deb scaffold**, with no maintainer scripts. M21 owns final packages, signing and release. Missing root-owned helper code is an actionable prerequisite. The desktop adapter invokes only root-owned M18 launcher operations through `pkexec`, after native confirmation, with no password/command IPC. Signed hello/installation identity checks follow setup/repair; removal checks expected code/credential/unit/socket absence. Audit, installed packages and user data remain. A missing graphical OS authentication agent (including WSL environments without one) is reported; the application never installs/reconfigures it.
