## Implemented contracts

- Guidance loads root plus canonical ancestor chains of declared assignment and retained requested paths, including both move paths. Directory targets include their own AGENTS.md. It does not scan recursively or claim complete discovery. Bounds: 100 retained targets, depth 16, 256 candidates, 32 present files, 32,000 bytes/file and 128,000 total. Missing versus empty is distinct; newly discovered absent chains do not regenerate otherwise unchanged proposals. Retained candidates are reread; present/change/failure invalidates stale approvals and acceptance. Nearest ancestor guidance applies only to its subtree; human/runtime authority remains higher. Invalid requested paths become correlated tool failures before inspection/dispatch, without poisoning valid guidance. Filesystem guidance failures still fail closed.
- Architect-only, execution-only maintain_instructions uses canonical AGENTS.md paths, exact versioned line patches, ordinary inspection/approval, dirty leases and history. Planning drafts remain prose. No general architect shell/write capability was added.
- read_file_range, revision-bound literal search_page, patch_file, delete_file and rename_file are registry-defined tools. Ranges preserve literal content and whole-file hash; patches preserve untouched bytes/CRLF. Search bounds discovered/queued entries as well as visited files, text, time and matches. Incomplete observations do not establish absence or an atomic source snapshot.
- Rename is guarded copy/remove with an absent destination, sorted locks, both leases, durable operation claim, exclusive creation, content write/fsync, repeated identity/hash checks and final source unlink. It is not atomic OS rename, full metadata preservation or proof against all external races. Partial files/directories remain uncertain; no overwrite or rollback cleanup is attempted.
- One move history record holds both paths privately and exposes destinationPath publicly. Undo validates both current identities/versions and claims transactionally before possible parent/file creation. Nullable expectedHash remains bound to the exact preview token. Partial reverse failures stay unknown, including after restart; both viewers receive events. Real Chrome exposed a Monaco teardown error on approval close; comparison models are now detached before their owned editor/models are disposed.
- start_process, process_status, process_output and cancel_process use an opaque UUID bound to project/chat/root-task/frame/native call. Start claims before setup; after all sandbox/guidance awaits, the final callback rechecks authorization and commits running immediately before PTY dispatch. No PID input, adoption, replay, host-shell fallback or second model scheduler exists.
- A private Symbol reservation excludes concurrent file/editor/shell/install/reset/removal effects. Actual namespace/broker cleanup precedes release; unconfirmed cleanup retains ownership. Missing-root normalization preserves app-only recovery after an already-deleted project directory; it does not authorize new filesystem effects.
- Processes use existing Linux sandbox/PTY infrastructure: maximum/default 600-second timeout, 64 retained handles/project, 64,000 output bytes, 128 output events, 16,000-byte UTF-8 pages and one-second waits. Backend keys stay out of child environments and are redacted across output chunks. Start/status/exit are not test-report evidence. Interrupted/uncertain effects block acceptance; restart only marks nonterminal claims uncertain. There is deliberately no generic process uncertainty reconciliation or evidence eviction.
- Pause, interruption, steering, guidance change and close stop owned jobs. Runtime outcome/native-publication failures abort and drain before publishing the original error. Secondary cleanup failure retains ownership/claim and secondary evidence; failed error-record persistence preserves the original rejection with an observer for detached execution. Already terminal observations are not rewritten as invented uncertainty.

See [API contract](../api-contract.md) for arguments, private/public types and bounds, and [architecture](../architecture.md) for integration. No legacy adapter, profile migration, automatic directory deletion or live-provider simulation was added.
