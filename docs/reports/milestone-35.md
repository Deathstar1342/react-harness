## Proposed fixed broker and HTTP contract

Only `preview_open`, `preview_read`, `preview_close` authenticated worker operations, bound to exact claimId/binding and current broker session, are proposed. Open takes only canonical relative request-target and approved port from the durable process action; no host/header/socket/command arguments. Broker looks up owned context, verifies resource inventory and invokes fixed image-owned `/usr/bin/python3 -I /opt/abyssus-worker/preview-http.py` via exact container exec. The helper receives JSON on stdin and performs GET only to worker loopback. Root private helper does not import project code, use project cwd/env, or inherit broker/provider secrets. Response data is untrusted and never execution evidence.

HTTP GET only, origin-form path/query <=2048 ASCII bytes. Reject controls/backslash/fragments/authority/dot segments/duplicate slash, malformed or nested percent encodings and encoded separators/dot/control aliases; reject reserved private/control path prefixes. Fixed outbound Host is `127.0.0.1:<approved port>`; fixed Accept and Connection:close; no incoming Cookie, Authorization, Origin, Referer, proxy, forwarding, upgrade or arbitrary headers. No redirects are followed; 3xx, 101 and invalid/duplicate/oversized response headers are rejected. Only bounded text/html, JavaScript, CSS, JSON, images and fonts; no Set-Cookie, Location, authentication, CSP override or arbitrary upstream headers survive. No POST/form submission, WebSocket, HMR, SSE, range streaming, service worker or download support in this first contract; show explicit Reload and explain this limit.

Limits proposed: 4 simultaneous fetches globally and 2 per preview; 16KiB response headers, 4MiB decoded body, 15s absolute fetch deadline, 32KiB broker pages within existing 256KiB authenticated wire bound, 8 retained response buffers/32MiB aggregate, 20s response-buffer TTL, monotonic exact offset and single-use close. Fixed helper stdout/stderr/input are bounded with deadline/owned CLI cancellation, not unbounded subprocess capture. Every page repeats ownership/session checks. Invalidation discards buffers before exact worker stop; late replies fail current generation checks. No private-state/PinnedPath/SQL/header-budget weakening.

## Proposed browser and Electron isolation

A separate ephemeral HTTP listener on literal `127.0.0.2` with random port and random per-preview capability origin path serves only a bound owned preview. It never serves app assets/API, accepts pairing/auth, sets cookies or forwards browser credentials. App transport token stays exclusively in trusted code; app cookies are host-only and /api-scoped and are not copied. Reject Host aliases/DNS/IPv6/mismatched port, unsafe Origin and non-GET. Capability is scoped to one renderer preview, not controller access; omit from logs/persisted DTOs and revoke on close/switch/expiry. Validate raw targets before URL normalization. CORS permits only the opaque sandbox origin `null` without credentials for module/assets; no app/API CORS grant.

Browser app embeds this distinct origin in `<iframe sandbox="allow-scripts">` (no same-origin/forms/popups/top navigation/downloads), with no referrer and an enforced preview response CSP: default none; scripts/styles/assets/connect restricted to the exact preview origin (inline scripts/styles needed by dev apps); objects/frames/workers/base/forms none; sandbox allow-scripts. Parent frame-src permits only the designated literal preview listener class. Relative URLs must preserve the preview capability; initial proposal uses a random listener per preview so assets can remain root-relative, with unguessable session identity supplied only to trusted embedding and strict parent/opaque-origin admission. This detail needs coordinator review before coding: opaque-frame requests cannot carry a secret header, and blanket capability-path rewriting must not become a JS/HTML security parser.

Electron uses a dedicated sandboxed WebContentsView panel/session per preview, no preload, nodeIntegration=false, contextIsolation=true, sandbox=true, webSecurity=true, webviewTag=false. Its session webRequest allowlist allows only exact preview origin for that exact contents/frame; denies all app/controller/broker/file/private/external URLs, WebSocket, permissions, downloads, service workers, redirects, popups and escape navigation. Main process alone attaches/positions/destroys view via strict sender-checked app IPC bound to backend session and DTO, never caller URL. App partition/CSP/bridge remain isolated. Browser sandbox/CSP cannot provide Electron's session-level request firewall; explicitly investigate browser WebRTC/navigation gaps and either enforce equivalent bounds or fail closed on unsupported browser features before claiming isolation.
