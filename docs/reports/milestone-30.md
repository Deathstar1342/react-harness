## Coordinator-reviewed contract

The trusted host owns source/destination selection. The Linux source adapter is an explicit interactive Python-stdlib command, `bash scripts/project-transfer.sh`, using the existing private source selection. It requires the already documented host Python prerequisite, never host Node, provisioning, a controller-selected path, or a host shell fallback. It prepares a manifest and asks for exact human confirmation before issuing a random one-use capability. Browser UI accepts that opaque code, not host filesystem paths. This is the interim **container source flow**. M30 defines the narrow `HostProjectTransferPicker` interface; M31 owns the actual container-connected native picker/runtime/channel. The legacy WSL desktop is not represented as container-connected.

Host-private ticket binds storage/session, source identity, exact reviewed manifest, destination parent identity, fresh managed UUID or exact export folder, and 15-minute expiry. Tickets are limited to 128 and durable transfer records to 512; exhaustion rejects instead of evicting unresolved records. Manifests are bounded to 32 MiB, 50,000 entries, 2 GiB selected bytes, 256 MiB per file, depth 32, relative path 240 UTF-8 bytes and component 120 bytes. Status returns at most 100 exclusions and their total count; the full list stays in the host-private manifest. Original host paths never enter controller/model receipts.

Linux descriptor-relative, no-follow traversal pins opened root/ancestor/file identities. Reject links, hard-linked files, special files, nested mounts, non-normalized names, case-fold collisions, Windows reserved names, ADS, trailing spaces/dots and unsafe path components. Copy ordinary executable bits into private destination permissions, stripping special permissions; no ACL/xattr/capability copying. Original bytes, mtime and modes remain unchanged; reads can update OS access times. Hashes, metadata and directory membership are rechecked; changed sources fail without publication. Staging uses a private owned location, verifies every destination byte and exact identity, then Linux `renameat2(RENAME_NOREPLACE)` publishes without replacing even an empty existing folder. Export stages on the destination filesystem for cross-filesystem support.

Default exclusions cover dependency/build/cache trees and sensitive configuration. Host review can explicitly include exact ordinary sensitive files, with their consequences. App storage, installation/runtime/config roots, credential directories and known application/provider credential locations remain forbidden. This is a path-policy guarantee, not arbitrary secret detection: placeholder documentation must remain importable, and no claim is made that ordinary files or Git history are secret-free.

Default imports preserve dirty working files and create a fresh inert Git repository. History requires separate explicit host opt-in and a warning that objects/index can retain deleted secrets despite working-file exclusions. Only normal local `.git` metadata is eligible: ordinary bounded objects/refs/HEAD/index/packed-refs/shallow bytes; generated inert config. No host/source Git commands, checkout, tree-to-path interpretation, hooks/config/log execution. Gitfile indirection, commondir, alternates, worktrees, modules, grafts, replace refs, unsupported/malformed metadata and unsafe links are rejected. Hooks, configuration, logs and ancillary metadata are omitted, with exclusions shown.

Broker consumes a ticket durably before copying. `transfer_begin/observe/cancel/receipt` accept opaque capability and managed identity only. Copy progress requires controller heartbeats, a deadline and broker ownership; cancellation drains before release. Interrupted broker claims become uncertain and never resume. Failed/cancelled copies retain unregistered residue and an explicit receipt; originals are never removed. No automatic registration, recopy or retry after registration COMMIT failure or reply loss. Successful import registration requires exact verified single-use receipt and atomic project/receipt mapping in SQLite.

Export holds Runtime pending-action/install/skill/process guards, tool mutation reservation, dirty-buffer validation and owned worker cleanup. Host additionally gates prepare/activate/install/reset for that exact exporting project and rechecks inactivity before publication. Unknown transport outcomes persist a backend quarantine instead of silently permitting work. The managed directory remains authoritative; imported source is never registered, mounted or deleted. Removal in container mode is restricted to an immediate managed workspace child.
