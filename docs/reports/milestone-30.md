## Accepted behavior and interfaces

1. Trusted host owns source/destination selection. `bash scripts/project-transfer.sh` is a supported explicit Linux source adapter using the existing private storage selection and Python standard library. It reviews the manifest and asks for exact human confirmation before issuing a random one-use capability. Browser UI accepts only that code. It needs no host Node/npm/provisioning or fallback shell. `HostProjectTransferPicker` is the narrow future interface; M31 owns the actual native picker/container connection. Legacy WSL desktop is not presented as container-connected.
2. Tickets bind storage/session/journal/lineage, source identity, reviewed manifest, destination-parent identity, fresh managed UUID or exact export folder and 15-minute expiry. Limits: 128 tickets, 512 durable records, 32 MiB manifest, 50,000 entries, 2 GiB selected bytes, 256 MiB/file, depth 32, relative path 240 UTF-8 bytes, component 120 bytes. Exhaustion refuses without eviction. Public receipts contain up to 100 exclusions plus total; original host paths remain host-private. Indexed token/project queries and one-record recovery avoid loading every large manifest for each observation.
3. Linux no-follow descriptor traversal pins roots/ancestors/files. Reject symlinks, hard-linked files, special files, nested mounts, non-normalized/colliding names, Windows reserved names, ADS and trailing spaces/dots. Copy ordinary executable bits into private permissions; strip special permissions and do not copy ACL/xattr/capabilities. Recheck hashes, source metadata and membership; verify staged bytes and identity before `renameat2(RENAME_NOREPLACE)`. Existing destinations, even empty, are never overwritten. Export stages beside the destination for cross-filesystem support. Original bytes/mtime/mode stay unchanged; reads may update OS atime.
4. Exclude dependency/build/cache trees and sensitive files by default. Host review may include exact ordinary sensitive paths; app/credential/runtime/config roots remain forbidden. This is path policy, not arbitrary secret detection. Placeholder documentation remains importable. Default preserves dirty working files with fresh inert Git. Separate history opt-in warns about deleted secrets in objects/index. Copy only bounded safe local objects/refs/HEAD/index/packed-refs/shallow and generate inert config; never execute source Git/hooks/config. Refuse malformed metadata, gitfiles, commondir, alternates, nested or case-alias `.git`, `.gitmodules`, modules, worktrees, grafts and replace refs. Show omitted hooks/config/logs/ancillary metadata.
5. Broker durably consumes authorization before a copy thread. `transfer_begin/observe/cancel/receipt` are strict opaque-code operations. Deadline/heartbeat/cancellation and ownership protect copying; restart leaves incomplete work uncertain without replay. Failures retain unregistered residue. Controller registers imports only from immutable, exact final, single-use receipts and atomically commits project/receipt mapping. COMMIT failure, response loss, concurrent redemption and changed receipt/identity never trigger automatic registration or recopy. Device/inode values are decimal strings with BigInt comparisons, including values above JavaScript's safe integer range.
6. `POST /api/project-transfers/import {name,code}`, `POST /api/projects/:id/export {code}` and explicit `POST /api/projects/:id/transfer-release {code}` are human APIs, not model tools. Container workspace settings expose `transferMode: source-code`. No host path browser endpoint or model-provided copy path is introduced. Imports are fresh immediate `/workspace` children; container removal is confined to immediate managed children.
7. Export holds runtime pending-action/install/skill/process guards plus the actual tool mutation reservation, dirty-buffer validation and worker drain. Host prepare/activate/install/reset refuse during export and publication rechecks inactivity. Unknown transport outcomes persist `transfer:reservation:<projectId>` across restart and block managed writes/delete/reset/export. Explicit release requires original code, storage/session/source identity, exact observed transfer/manifest, terminal host thread drain or a durably tombstoned unused grant. Missing/changed host journal cannot fabricate no-effect proof. Lost release acknowledgement/COMMIT retains quarantine. Release never recopies, deletes residue, registers a project, resolves unrelated uncertainty or claims unknown export success.
8. A host-private original-folder index (128 records/1 MiB) binds storage/journal/lineage identity and is atomically written/fsynced before an import ticket. It survives expiry, removal and restart with no eviction. Interrupted grant may retain a conservative orphan record. Missing/corrupt established provenance refuses startup/selection/admission without reset. Shared interprocess locking covers selection, confirmation, admission and full copy/publication; admission refuses lock contention without blocking broker heartbeat/cancel. Export rechecks retained originals and destination ancestry before staging/publication. Export anywhere inside an original tree is refused. Missing/renamed/replaced original roots conservatively block export, while normal managed editing/execution continues. Arbitrary moved-original tracking is not promised.
9. Source mount alias handling reads `/proc/self/mountinfo`: the most-specific containing mount must have filesystem root `/`; subtree binds/subvolumes refuse explicitly. Ordinary whole-filesystem roots remain allowed; full-root alias overlap is checked by device/inode ancestry. Managed storage is not rejected merely because it is a mount. Mocked mountinfo fixtures are policy tests, not real bind-mount device acceptance. No workstation mount changes were made.
