## Concrete contract for review

- **Scope and capture boundaries:** explicit human Capture in the project checkpoint panel, with a bounded optional label and an existing project chat as provenance. Capture only a registered managed project in container mode (portable fixtures also live beneath the configured managed workspace; direct execution mode grants no external-root exception). No arbitrary root/path argument, model checkpoint tool, automatic command/task launch or auto-restore. Capture is a deliberate idle task boundary; opening/listing never captures. Store project ID, root directory identity, chat/human provenance, timestamp, policy version and exact manifest digest. Capture is observation, never verification/approval authority.
- **Manifest and exclusions:** coherent complete set of eligible regular UTF-8 source files, sorted canonical relative paths, SHA-256 and exact UTF-8 bytes, file mode. Include safe AGENTS.md and `.abyssus/skills` source/resources. Exclude Git metadata, app/provider/private ledgers/runtime databases, credential paths, dot-private state, dependencies/build/cache/output directories using a fixed versioned policy. Return bounded excluded path/reason counts; do not ingest excluded content. Reject unexpected symlinks/junctions, hard links, special files, case aliases, invalid components, unstable reads, binary/oversize eligible code files, excessive depth/count/bytes. Never call an incomplete eligible set complete. Enumerate twice and compare file content/identity/tree revision under the same admission gate before publishing.
- **Bounds/storage:** use existing private `state.sqlite` only, checkpoint manifest/content and restore journals under fixed trusted state keys; no new private directory, file, DB, host API or worker mount. Initially 512 eligible files, 256 KiB per file, 8 MiB aggregate UTF-8 content, 10,000 visited entries, depth 32, bounded 200 KiB preview diff; fail whole capture/preview rather than truncate eligible sets. Up to 8 checkpoints / 32 MiB per project and 64 checkpoints / 64 MiB application-wide, measured serialized bytes; individual serialized manifests are capped at 12 MiB. Retain at most 32 restore journals per project / 64 application-wide, individual serialized journals at 24 MiB, and 64 MiB total serialized journal PLUS actual normal file_change summary/snapshot copies; refuse further restore at that bound. Expired in-memory previews max 100, five-minute lifetime, lost on restart.
- **Retention:** oldest unreferenced captures may be removed transactionally only during explicit capture. Never remove a checkpoint referenced by *any* retained restore journal (including claiming/uncertain/done), runtime evidence or current preview. Unknown references fail closed. Journals and uncertainty are never TTL-evicted; quota pressure refuses new work. Existing project removal may delete only resolved unreferenced checkpoint state; unresolved restore blocks project/chat removal. No generic uncertainty release endpoint.
- **Idle writer admission:** use Runtime exclusive project edit plus existing tool project mutation reservation and cleanup/drain gate. Reject active/awaiting-approval chats, pending decisions/executing native calls, process ownership/uncertainty, export reservation, unresolved file/skill/install effects and active/uncertain installs. Existing worker/shell cleanup must confirm teardown before observation, not assume idle workers cannot write. Reject dirty editor leases/active file operations, prevent new editor/worker/tool writers throughout gate and recheck bindings after drain. Restore uncertainty durably blocks further project mutation, exports/removal and runtime dispatch across restart.
- **Preview/fresh human decision:** authenticated POST preview reads current eligible set and integrity-checks immutable checkpoint; computes additions/removals/modifications (moves shown as remove/add) and bounded exact diff. Issue opaque one-use server token bound to project/root identity, checkpoint digest, full current tree identities/hashes/modes, project evidence revision, exact change list, expiry and existing chat. Return no private journal/provider/raw-ledger data. Explicit authenticated Restore POST must echo token + revision + checkpoint ID + confirmation `restore-files`; no model/prose provenance. Re-enumerate current complete tree and recheck application revisions/leases/reservations/checkpoint integrity before durable intent and before file dispatch. Later edits invalidate token; fresh preview can deliberately authorize their replacement. Directory/file topology collisions refuse safely before claim.
- **Restore journal and versions:** durable transaction claims one restore journal containing exact immutable before/after snapshots and checkpoint reference, appends normal `file_changes` recording rows before first effect, consumes preview. Use existing version/hash/no-follow/lease-aware WorkspaceFiles saves/removes inside the same held project gate. Delete extras deepest first, then restore target files; preserve Git metadata/index, excluded files, empty directories, chats/install/external effects. No git reset/clean. After all files and final full-set validation, one transaction confirms rows/journal, appends file_changed events/history and invalidates workspace/goal/guidance/selected-skill evidence using normal Runtime notifications. Restore is a coherent *reviewed target*, not a claim of cross-file OS atomicity.
- **Failure/restart:** persist claim before any filesystem effects. Pre-claim COMMIT failure has no target effects. Any post-claim error, partial effect, lost final COMMIT/reply is retained as uncertain (or durable done if COMMIT succeeded); no automatic replay, rollback or generic waiver. If uncertainty persistence itself fails, original claiming journal and recording rows remain the durable barrier. Startup maps claiming to uncertain without touching project files and invalidates relevant evidence; project admission inspects claiming as blocked even before recovery. Reads/absence/capture cannot clear uncertainty. Final notification loss cannot downgrade durable completion. Do not start workers/provider calls during recovery.

No new private target or absent-path authority is introduced. Async filesystem boundaries use `runNativeOperation` and assertNativePath(projectRoot,false), independently of private observations. A private target failure poisons the existing native session; no retry or recovery authority comes from snapshot reads. ## Coordinator refinements applied before freeze

The coordinator reviewed `aad5223` and the initial implementation and approved the direction with six corrections. `server/checkpoint-state.ts` now limits SQL-returned rows, per-record bytes and total bytes BEFORE duplicate-key-rejecting JSON parsing. Complete catalogs use strict checkpoint/journal schemas, exact key/ID/project/root/integrity and checkpoint reference validation; unknown/malformed/oversized/truncated evidence fails closed, including on mutation admission and restart. Project/chat rows are bounded to 16/32 KiB, 64 chats per observed project; context up to 257 rows, 2 MiB each / 8 MiB combined. Approval/process/skill/install auxiliary observation is bounded (256 rows, 4 MiB total, 128 KiB process/approval/install and 500 KiB skill records; installs max 100). Retention reference scans cap each source at 512 rows, 2 MiB each / 8 MiB total and refuse unknown coverage, never interpret absence as authority. Actual journal and normal file_change serialized copies count toward retention quota. Current project evidence bytes are hashed privately, never returned.

Managed workspace membership is mandatory in every execution mode. The source-text policy explicitly excludes common binary image/font/audio/video/archive/native-object/3D assets by extension (including PNG/JPEG/WebP/ICO, fonts, MP3/MP4/WAV, PDF/ZIP/JAR/WASM/EXE/DLL and GLB/FBX). Their bounded paths/reasons are reported without reading content. SVG/plain text assets remain eligible. Unknown binary extensions, unreadable/oversize eligible code, links/special entries and incomplete traversal reject the complete capture. This is a source-text checkpoint, never a backup of binary assets. Ordinary `bin/` source scripts are eligible; known dependency/build/cache outputs remain excluded.

Permission restoration is a separate effect after the guarded save. It opens no-follow, bounds and hashes descriptor bytes, compares descriptor/current confined target device/inode/ctime/mtime/mode/size/link/type, repeats the exact durable journal claim after all awaited observations, then calls descriptor chmod. A stale claim or target substitution cannot authorize that second effect. Newly saved bytes/permissions remain under the same multi-file uncertainty journal.

The checkpoint barrier is enforced by Store removal/history guards; Runtime submission/resume/edit/process admission; WorkspaceTools mutation guard, worker cleanup and dirty-editor gate; install dispatch/reconciliation; skill save/promotion; managed export/reset/removal routes; and startup. Reads never clear a barrier. Explicit fresh human preview may replace the exact shown current edits, while any later content/identity/project revision change invalidates the token. Captures/journals retain explicit human source; restore journals bind confirmation and a private token hash. Ordinary model prose has no checkpoint handler.

Targeted progress: initial 11 disk/filesystem tests pass before the bounded-state refinement; subsequent refinement validation is ongoing. Initial fixture failures are preserved in tool output and external D receipts: source-contained temp roots correctly rejected by sandbox; Git exclusion count needed to include .git; Windows file symlink needs privilege, replaced by a real unprivileged junction test.
